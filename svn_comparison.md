# Сравнение Git и SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это всего лишь **указатель на коммит** (файл с хешем,
~41 байт). Создание ветки не копирует файлы и не дублирует историю,
поэтому операция мгновенная и почти не тратит ресурсы.

В SVN ветка — это **физическая копия директории** в репозитории
(`/trunk`, `/branches/...`). Создание ветки копирует все файлы
на сервере, а переключение — выгружает рабочую копию. При большом
проекте это долго и нагружает сервер. Поэтому в SVN ветки используют
редко, а в Git — постоянно.

---

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

**Нет.** SVN — централизованная система: вся история и метаданные
хранятся только на сервере. Локально у разработчика лишь рабочая копия
последней версии. Без сети нельзя ни закоммитить, ни посмотреть
историю, ни создать ветку. Команда `svn commit` сразу потребует
соединения с сервером.

В Git наоборот: у каждого полная копия репозитория, поэтому коммиты
и ветки делаются офлайн, а сеть нужна только для `push` / `fetch`.

---

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

1. **Legacy-проекты в госсекторе и банках** — миграция дорогая,
   старые системы продолжают поддерживать на SVN.
2. **Хранение больших бинарных файлов** — SVN работает с крупными
   бинарниками без раздувания репозитория.
3. **Жёсткий контроль доступа к папкам** — в SVN права настраиваются
   на отдельные подкаталоги, в Git — только на весь репозиторий.
4. **Команды с низкой квалификацией в Git** — порог входа ниже,
   линейная история, простые команды.
